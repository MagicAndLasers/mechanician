What's new in 0.26.16

The library update no longer stops on a file it cannot read

  • 0.26.15 fixed this for images and artifacts, and the update then stopped on a different kind of file instead. The rule was written separately for each kind, so fixing one left the others.
  • There is now one rule for all of them. Any file Mechanician cannot read is recorded and the update carries on, whether it is an image, an artifact, a workspace, or a scheduled task.
  • Nothing is thrown away. The exact bytes of every unreadable file are kept in the rollback copy beside your library.
  • This does not lose anything you could otherwise see. A file Mechanician cannot read now is a file it could not read before the update either.

The update window closes when it should

  • If the update stopped, Mechanician opened your library but left the progress window sitting on top of it, which looked like it was still running and still failing. That window now closes.

What still stops the update

  • A conversation that cannot be read, or a scan that cannot be completed. Those decide what you see, so continuing without them could quietly change your library rather than skip one file nobody can open.
