What's new in 0.26.19

Resumed Claude turns can start sooner, long conversations do less repeated work, and Codex provider recovery is more tightly bounded.

Activity timelines read consistently

  • Text inside coloured activity spans is now white throughout the timeline. A subtle dark edge keeps labels readable on both quiet and saturated spans without changing their phase and tool colours.

The one-time library update completes more directly

  • The migration could appear stuck at 32% while it repeated whole-library collection and database checks it had just completed. It now reuses the exact verified database, performs one full rollback collection, and releases import memory before that collection.
  • The progress window names the file, recovery, and database checks within the formerly opaque phase and shows when the engine last crossed a real work boundary.
  • A previous refusal no longer produces a migration window with no worker behind it. Interrupted cutovers always resume, while normal app updates do not repeat an unchanged refusal.
  • Media left behind after its Conversation was removed is now preserved as verified recovery data instead of permanently refusing the migration. This was the concrete blocker reproduced from the affected production library.

Resumed Claude turns can start sooner

  • Every resumed turn sampled during the performance audit repeated a live context check, even when the preceding successful turn had supplied a safe measurement. Those checks held prompt delivery for 486–926 milliseconds, with a median of 627 milliseconds.
  • Eligible turns now reuse that terminal measurement when the model, session, context window, configuration, and successful completion all agree.
  • Anything uncertain—including compaction, retries, resets, concurrent use, or an ambiguous model catalogue—still uses Claude's live check. No context or compaction safety threshold was widened.

Long conversations do less repeated work

  • As an answer streamed into a large conversation, every incoming event rescanned the conversation's transcript and activity history just to assign its order. Mechanician now seeds that order once and allocates subsequent events in constant time.
  • Large live responses update the visible transcript at an adaptive rate instead of repeatedly rebuilding accumulated Markdown at display-frame speed. Provider events are still accepted immediately, and tools, questions, completion, navigation, and quit boundaries still land the exact pending text before proceeding.
  • When a completed response scrolls back into view, Mechanician can reuse its finished Markdown document instead of parsing and highlighting it again. In a roughly 370 KiB benchmark, repeat realisation fell from 744 milliseconds to 348 milliseconds. The cache is strictly bounded and live responses never enter it.

Codex is lighter when inactive and safer when unstable

  • A Codex App Server that initialised successfully and then exited quickly could keep triggering replacement processes. Restart pressure now carries across short-lived handshakes, automatic replacements stop after a bounded series, and the budget returns only after the replacement stays healthy.
  • An explicit turn or Connect action retains one recovery attempt. If Codex exits during sign-in or MCP authorisation, the exact operation now finishes with an error instead of leaving a browser flow or spinner waiting for minutes.
  • When you select another provider, an idle Codex lane releases its App Server after five minutes and wakes it again on demand. The selected lane stays warm, active work postpones cleanup, and the owning daemon remains alive so detached background work stays stoppable.

Stopped background work reconciles correctly

  • A background process could stop successfully while its old row remained in the Tasks panel. The acknowledging provider now clears its row immediately and forces the next ordinary snapshot to reconcile it.
  • If the process ignored the first termination signal, that snapshot shows it again with a working Stop control. No additional process polling or provider constraint was introduced.
