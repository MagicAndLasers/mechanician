What's new in 0.10.0

  • Work survives the window. One signed per-user Runtime Service now owns provider processes, accepted turns, ambient scheduling, and terminals independently of the app's windows.
  • Reliable reconnect and replay. Versioned authenticated IPC, durable command admission, idempotent event replay, and explicit cancellation reconciliation prevent accepted work from disappearing or being applied twice after a restart.
  • Stronger Codex Ultra recovery. Provider generations are fenced explicitly, quiet work remains undisturbed, and a lost provider surfaces each affected activity once as recoverable instead of leaving the interface stuck.
  • Terminal sessions reconnect safely. Terminal identity and controls persist across window and app relaunches, while raw output uses a separate bounded in-memory channel so high-volume PTY data never bloats the durable event ledger.
  • Hardened runtime boundary. The app and helper validate identities, protocol versions, frame limits, signed resources, and privacy-safe diagnostics before running the bundled provider worker.

Anthropic sign-in, fixed

  • One button everywhere. Signing in to your Anthropic account is a single button on every surface — the error card, the Connect to Anthropic card, the Accounts panel, and Settings. No terminal commands, ever.
  • Conversations resume themselves. A conversation interrupted by an expired sign-in continues automatically after you reconnect, including anything you queued in the meantime.
  • Truthful account status. An expired credential shows “Sign-in required” instead of “Configured”, Connect validates an already-valid credential without opening a browser, and API keys can be added directly in the Accounts panel.
