Executive conclusion

The runaway lsof defect is fixed in 0.26.17, and 0.26.18 removes process polling from untouched lanes. No active lsof children were observed, and the monitor prevents overlapping polls, caps orphan probes, caches misses by process generation, times out each probe, and aborts on shutdown. Post-0.26.18 follow-ups repair the leading Claude turn-latency regression, reclaim the heavy Codex App Server stack after five idle minutes on an unselected lane, and remove a newer O(provider events × transcript size) capture-order regression. The selected Codex lane remains eager, and its owning agentd stays alive as the Stop authority for detached work.

How much to trust the Fable result

Fable’s 13 finder agents completed and produced 79 findings: 8 high, 26 medium, and 45 low. Many repeated the same root cause. Its planned 10-agent adversarial verification phase then hit the Claude usage limit and returned zero verdicts. This report therefore treats the finder output as leads, not proof, and ranks only claims verified against the current source or live measurements.

Its feature review was directionally strong: 13 of 15 requests were judged landed. The partial items were FR-216’s Claude context preflight optimization and route-aware provider facts.

Ranked current findings

1Claude context preflight misses on resumed turns Identity hardening implemented

Eleven field samples blocked prompt delivery for 486–926 ms (median 627 ms). All ten resumed samples missed with no_cached_usage; no successful cache-store observation was found. Prompts were only 3–189 tokens, so increasing the 16K eligibility cap cannot solve the observed miss.

Verified root cause: ordinary turns selected opus[1m], but the cache admitted only syntactically stable model IDs; the SDK also reports the 1M context identity and serving generation on different surfaces. The alias gate therefore prevented every observed claim and store.

Follow-up repair: resolve alias-shaped queries through the SDK’s already-initialized catalog, retain exact requested configuration separately, and reuse one terminal sample only when resolved generation, terminal window, session, command surface, and successful root terminal all agree. Alias remaps, ambiguous terminal results, compaction, retries, resets, concurrency, and session changes fail closed to live getContextUsage(). Reasoned claim/store logs make remaining misses measurable. Eligible resumed turns avoid the measured 486–926 ms control delay; the prompt-limit safety policy is unchanged.

Identity hardening: the fast path now requires exactly one matching row in the current query’s initialized catalog even when the picker value looks like an explicit version. Missing initialization, an absent row, and identical, conflicting, or malformed matching duplicates all fall back to live getContextUsage(). Cache seeding also requires the usage baseline itself to match the query’s resolved serving identity; an alias-shaped echo of the requested picker value is no longer accepted as proof. Deterministic daemon fixtures cover the positive Opus/Fable mappings and every new fallback. This tightens only optional cache eligibility: provider-native compaction and the existing prompt/window safety policy are unchanged.

2Provider process and lane residency Follow-up implemented

A full ps snapshot measured about 50 ms and 346 KB. Four daemons produced 48 snapshots/minute—about 4% of one CPU core and 16.6 MB/minute of text parsing while idle. The live Mechanician tree summed to roughly 1.47 GiB RSS across the app, four agentd processes, and Codex server/host processes.

Patch impact: untouched lanes now do no process-table fork or parse. A lane that has accepted work continues polling, preserving background-process discovery. Codex child recovery retains exponential backoff across short-lived successful handshakes, permits at most six automatic replacements until one remains healthy for 60 seconds, and gives later explicit turn, account, authorization, or real lane-selection demand one retry without reopening an automatic burst. Provider exit terminalizes the exact browser-login and MCP OAuth owners instead of leaving a five-minute spinner or publishing duplicate terminal events.

Inactive residency policy: the selected Codex lane stays eager. When another lane is selected, a fail-warm advisory starts one five-minute deadline and releases only the App Server child. Accepted turns, prewarms, outbound and server-initiated JSON-RPC, login/OAuth browser holds, permissions, questions, computer use, and ambient mutations all lease the child until they settle. Release clears process-local thread proofs and uses bounded TERM→KILL cleanup. Explicit demand wakes one child; repeated ready advisories, automatic catalogs, and prewarms cannot shorten backoff or reopen the restart circuit. Older app builds send no advisory and therefore retain the previous always-resident behavior.

Installed dogfood gate and follow-up repair: never reap the owning agentd after accepted work; its in-memory tracker is the only trustworthy Stop authority for detached jobs, and a replacement cannot safely adopt older processes. Unconditional demand-only startup is also rejected because it moves roughly 600 ms—and sometimes more than a second—onto an unpredicted first turn. The signed package ran authenticated Codex dynamic tools through its bundled App Server and codex-code-mode-host, adopted a real workspace-rooted process after it detached to launchd, and delivered Stop to the exact pid while the daemon, App Server, and host remained stable and no lsof child lingered. That exercise exposed a stale Tasks row: the app did not remove its acknowledged source and the daemon could coalesce the following empty snapshot. The repair removes only the acknowledging daemon's UI copy, retains the tracked process generation until ps proves exit, and invalidates publication coalescing so the next ordinary serialized poll emits once whether the process ended or ignored SIGTERM. Another daemon's independently tracked copy stays visible, and reconciliation adds no process-table or orphan probe beyond Stop's existing pre-signal identity validation. The rebuilt signed dogfood closed the gate twice: an ordinary detached process cleared immediately and stayed absent, while a fixture that ignored its first SIGTERM was removed, remained alive, reappeared with the identical signature after 4.5 seconds, then died and stayed absent after its second Stop. The app, daemon, App Server, and code-mode host PIDs remained stable throughout; no lsof process appeared.

3Per-event capture chronology scan Follow-up implemented

An August 3 chronology change allocated a record-local capture ordinal for every accepted turn event, then found the next value by rescanning all transcript rows, refinement fields, activity records, and subagents. On the measured 9,421-row live record this put an O(transcript) scan—and temporary flatMap/compactMap arrays—on the main actor before token coalescing. This recent regression is a stronger explanation for “latest builds feel slower” than the older renderer debt alone.

Follow-up repair: distinguish provisional reservations from records whose durable evidence has actually been seeded, preserve the maximum of persisted, retained, and uncommitted in-process chronology, then allocate every provider event in O(1). Modern durable records seed from their save-time watermark; Legacy launch computes retained maxima off the main actor with one allocation-free loop. All authority, SQLite-rehearsal, Legacy-load, hydration, replacement, and deletion seams advance or clear the cache explicitly. Large-record tests prove 1,001 consecutive allocations perform no additional scan, async publication cannot reuse an ordinal reserved before inventory readiness, replacement records can only advance the seed, and UInt64.max remains saturating.

4Long-turn transcript and Markdown work Third stage implemented

Streaming flushes rebuild transcript chunks across the entry list, while the active assistant cell reparses the accumulated Markdown on every visible tail revision. Equal-value @Published writes and a no-op Set removal also bypassed the intended coalescer at raw provider-token rate; extending a published entry emitted twice.

Follow-up repair: no-op working/stall transitions no longer publish, one transcript mutation emits once, and presentation remains 60 Hz for small turns while stepping down across 16/64/256 KiB/1 MiB response bands and 512/2,048/8,192-row transcript bands. Provider ingress is never delayed or backpressured. A new assistant row reserves the first delta’s chronology before any delayed paint; frame, tool, permission, question, system-notice, terminal, navigation, window-close, and quit boundaries synchronously land exact pending bytes and close the row before later prose. Presentation-only row revisions reuse identical TextKit Markdown, and syntax highlighting precomputes comment tokens once per render.

Measured finalized-row cache: an opt-in ~370 KiB mixed Markdown benchmark separated renderer construction (395 ms) from TextKit installation and layout (347 ms) on this Mac; optimized 64 KiB fixtures independently put construction at 50–57% of fresh repeat-realization cost. A coordinator-owned MRU now retains only pristine finalized assistant documents under exact conversation-scoped row, source, and scale identity. It is capped at 32 documents and a 16 MiB deterministic weighted retained-cost budget, with independent 512 KiB source and rendered-length guards; the budget is deliberately not presented as RSS. It prunes with the row-ID set the coordinator already builds on structural changes and clears on teardown. Live prefixes never enter or query it, an oversize document adds no cache copy, and Find mutates only the cell's private NSTextStorage. On the long fixture, a cache hit reduced fresh render/install/layout from 744 ms to 348 ms (53%); attribute-scan-free constant accounting admitted the cold document in 748 ms, within 0.5% of the uncached path in the recorded run. First realization remains uncached, while active streaming, width reflow, provider ingress, and harness behavior are unchanged.

Resident-publication repair: the full resident conversations cache is no longer itself @Published; no source consumer subscribed to that projection. Hidden provider deltas remain synchronous and exact in memory, advance their existing revision, and share one process-wide 250 ms presentation batch, but summary-neutral session, context, activity, and tool-state changes no longer invalidate every bridge and window per event. The batch derives and assigns the complete summary array at most once. If no summary changed, searchable transcript text emits one narrow ID-set pulse consumed only by mounted sidebars with an active search; if any summary changed, that ordinary publication already refreshes every search and suppresses the extra pulse. Durable summary-neutral mutations, hydration, and batched eviction each retain one explicit semantic notification, while the runtime-only wait-check timestamp opts into one narrow notification without becoming a giant-record disk write. Deterministic regressions drive 1,000 live mutations with zero immediate fan-out, prove multi-conversation and mixed-batch coalescing, find assistant text beyond an unchanged 240-character snippet, and verify terminal persistence cancels pending summary and search work without a later duplicate.

Remaining recommendation: retain incremental transcript chunks and stable Markdown blocks, reconciling canonically at terminal state. Adaptive cadence, finalized-row reuse, and isolated resident publication bound current work but do not make the remaining full projection/parser incremental. Dogfood measurements should tune the heuristic bands; profiling can decide whether the one-time MainActor scan for an abnormal/legacy hydrated record without a durable watermark is worth moving into every hydration payload.

5FTS projection write/storage amplification Medium

projections.db is about 1.50 GB with 89,887 FTS rows. conversation_id is UNINDEXED; replacing one conversation scans the FTS table (about 0.17 s warm here) and retokenizes its entries. The durable outbox coalesces bursts, so Fable overstated this as a rebuild on every commit.

Recommendation: map conversation IDs to indexed rowids and apply per-entry deltas. This is a schema project, not a safe mechanical patch.

6Remaining harness constraints and mirrors Medium

  • Suspect: Codex item/permissions/requestApproval is always answered with an empty grant, dead-ending provider-native sandbox escalation.
  • Deliberate: Mechanician’s out-of-sandbox Read/List/Search/Write/Edit/Bash tools are withheld from Codex because Codex has native equivalents; adding them would bypass its sandbox.
  • Drift risk: OpenAI model/context/effort mirrors and duplicated Swift/daemon context-window rules can hide new provider capabilities.
  • Costly but intentional: Claude warm spares and per-window isolation trade memory for latency. Historical claim rate was about 64%; tune with telemetry rather than deleting prewarm wholesale.

Corrections to high-severity or repeated Fable claims

  • Integrity is not a first-paint blocker. Warm inventory was ~0.11 s and integrity ~0.23 s on a 692 MB / 132k-event library; integrity runs after readiness, though it can contend on the serial store queue.
  • Legacy triple writes are retired. They did not affect marker-active SQLite installations, and the current candidate removes the Legacy product writer and shadow-coordinator path entirely. Unmigrated roots must complete cutover under 0.26.21.
  • Codex guidance is smaller and less frequent than claimed. It is ~2,948 bytes / ~737 tokens at thread start or resume, not ~1,270 tokens on every turn.
  • An upgrade-wide Codex replay was not substantiated. Replacement proof is process-local and driven by configuration/revision changes.
  • Spotlight is not a leading current bottleneck, and deferred migration is gone. Spotlight's remaining work is conditional or utility-scoped; current builds have no deferred migration worker.
